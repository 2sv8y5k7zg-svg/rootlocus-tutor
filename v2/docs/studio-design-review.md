## 변경 이유

기존 v2의 시네마틱 디자인이 랜딩에 집중되어 있고 학습 화면은 밝은 카드 배치로 구성되어 있어,
전달함수 입력부터 9단계 풀이까지 동일한 시각 경험이 이어지지 않았다.
학습 도구의 중심을 어두운 s평면 무대로 바꾸고, 밝은 풀이·입력 영역과 구분한다.

## 실제 코드 변경

| 파일 | 역할 |
|---|---|
| web/css/studio.css | 학습 페이지 전용 색·배치·그래프 도구·모바일·집중 보기 |
| web/learn.html | 도구 막대, 재생 버튼, 움직임 줄이기, 접근성 설명, 새 자산 연결 |
| web/js/graph.js | 단계별 드로잉·애니메이션 취소·캔버스별 색·정확한 K 극점 표시 |
| web/js/studio-motion.js | 재생/일시 정지, 집중 보기, OS 모션 설정, 탭 숨김 처리 |
| web/js/learn.js | 기존 학습 흐름과 새 도구 연결, 오래된 K 응답 차단 |
| tests/studio-smoke.cjs | 브라우저 대역으로 상태·좌표·재생·API 응답 순서 검사 |

학습 페이지에만 studio.css를 추가한다. 공유 graph.js는 캔버스에 전용 색 변수가 없으면 기존 밝은 팔레트를 사용한다.
랜딩 스크롤이 지정한 progress를 setData에서 보존한다.
기존 오프라인 빌더는 /static/ CSS·JS 태그를 읽어 인라인 처리하므로 새 자산에도 같은 방식이 적용되는 구조다.
오프라인 HTML 재생성 자체는 아직 실행하지 않았다.

## 모션과 수학의 경계

- 2단계: 극점·영점 좌표를 고정한 채 투명도와 주변 고리만 변화시킨다.
- 3단계: 실수축 근궤적의 표시 구간을 펼친다.
- 4단계: 점근선을 중심에서 해당 각도로 펼친다.
- 5~7단계: 핵심 점의 고리와 화살표 표시로 새 결과를 강조한다.
- 8단계: Python이 제공한 가지 배열을 동일한 K 인덱스까지 순서대로 그린다.
- 9단계: 재생/일시 정지 및 슬라이더로 Python 표본의 폐루프 극점을 보여 준다.
- K 직접 입력: 가까운 표본을 정답처럼 표시하지 않고 /api/poles 응답의 re, im을 사용한다.
- 재생 속도는 시연용이다. K 표본은 균등하지 않으며 실제 시간 응답을 의미하지 않는다.
- 그래프에는 회전·원근 변환·스플라인 보간·임의 좌표 흔들림을 넣지 않는다.
- 가로/세로 축척을 동일하게 유지한다.
- 새 백엔드 계산이나 외부 AI 호출은 추가하지 않는다.
- GPU 3D·영상 자산·추가 CDN을 사용하지 않는다. 모션은 Canvas requestAnimationFrame과 브라우저 패널 애니메이션으로 처리한다.

## 실행한 검사

이 작업의 Python/쉘/브라우저 실행 환경은 사용 불가능했다.
JavaScript 실행 환경에서 tests/studio-smoke.cjs의 runStudioTests 본문을 동일한 수정 소스와 함께 실행했다.
Node CLI 명령 자체를 실행했다는 뜻은 아니다.

- JavaScript 구문 분석: graph.js, studio-motion.js, learn.js 통과.
- 브라우저 대역 상태 검사: 38/38 통과.
- 레티나 배율 상한, 좌표 변환 왕복, 동일 축척.
- 1~9단계 그리기, Canvas 상태 균형, 엔진 입력 데이터 불변.
- 단계 이동 시 이전 RAF 취소, 모션 줄이기, 숨겨진 탭 중지.
- K 표본 순서 재생, 종료·일시 정지 때만 검산.
- 집중 보기 진입·초기화, OS 모션 설정 변경.
- 오래된 K 응답·다른 문제 응답 폐기, 직접 K 입력 대기·정확한 좌표 적용.
- 음수 K 차단, 서버 연결 오류 후 표본 그래프 유지.

이 38개 항목은 수학 검증 문제 38개를 뜻하지 않는다.
기존 저장소의 Python 테스트 통과 숫자를 이번 변경의 실행 결과로 사용하지 않는다.

## 실행 환경에서 후속 확인

v2 폴더에서:

```text
node tests/studio-smoke.cjs
python -m pytest tests -q
python tools/build_offline.py
python run.py
```

브라우저에서 /learn을 열고 다음 순서로 확인한다.

1. 예제 선택 → 1~9단계를 빠르게 오가며 이전 애니메이션 잔류 여부 확인.
2. 8단계 재생 중 3단계로 이동, 재차 8단계 진입.
3. K 재생 → 일시 정지 → 슬라이더 이동 → 임의 K 직접 입력.
4. 네트워크 지연을 주고 K를 연속 변경한 뒤 숫자·극점 일치 확인.
5. 그래프 집중 → 복귀 → 다른 문제 → 새 문제 선택.
6. OS 움직임 줄이기 및 페이지 체크박스, 다른 탭 이동.
7. iPad에서 캔버스 위로 세로 스크롤.
8. 랜딩의 실제 그래프 미리보기 및 오프라인 빌드 회귀 확인.

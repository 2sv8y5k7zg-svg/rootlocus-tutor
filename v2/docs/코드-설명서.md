## 2. 계산 엔진 실행 흐름 (`engine/solver.py analyze`)
1. `parse.py` 입력 해석 → K·N(s)/D(s). 약분하지 않고 읽어서 극점·영점 상쇄를 잡아냄. 범위 밖이면 이유와 함께 중단
2. `steps.py` 1~6단계: 특성방정식 → 극점·영점(`roots.py`) → 실수축 → 점근선 → 이탈점 → 출발각
3. `routh.py` 7단계: K를 문자로 둔 Routh 표, 안정 범위(임계값 사이 시험값으로 부호 확인), s=jω 대입으로 교차점
4. `branches.py` 8~9단계: K를 늘리며 근을 구하고 가까운 것끼리 이어 가지를 만듦, K별 폐루프 극점
5. 단계마다 **다른 방법으로 한 번 더 계산해 비교**(check). 예: 극점은 인수분해 ↔ numpy 고유값, 이탈점은 그 K에서 정말 중근인지 대입, 출발각은 그 방향으로 조금 움직인 점에서 각 조건 확인

## 4. Python ↔ JavaScript 통신
모두 JSON. 예) 채점
```
요청  POST /api/check {"problem": {"text": "K/((s+1)(s+2)(s+3))"}, "field": "centroid", "answer": "-6"}
응답  {"status": "incorrect", "expected": "−2", "student": "−6", "diagnosis": "(n − m)으로 나누지 않았습니다."}
```
K 슬라이더는 서버가 미리 보낸 가지 점을 고르기만 하고, 손을 뗄 때 한 번 `/api/poles`로 정확한 값을 받습니다.
랜딩 스크롤 연출은 서버에 요청하지 않습니다.

## 5. AI 요청과 검증 흐름
1. 사진 업로드 → 동의 확인 → `/api/ai/recognize` → Gemini가 JSON 스키마대로 구조 추출
2. 엔진이 그 구조로 T(s), 특성방정식을 **미리 보여 주고**, 학생이 고치거나 확정해야 계산 시작
3. 손글씨: Gemini가 학생 값·AI 의심 여부를 JSON으로 → `ai/verify.py`가 값마다 `grader.check`로 엔진 채점 → 일치/불일치/인식 확인 필요/검증 불가
4. 힌트: 엔진 근거와 팀 힌트를 함께 보내고, 답에 엔진에 없는 숫자가 있으면 AI 답을 버리고 팀 힌트 표시
5. AI 실패(키 없음, 한도, 네트워크)는 모두 팀 힌트·직접 입력으로 대체 → 계산 기능은 항상 동작

## 8. 본선 예상 질문과 답
1. **AI가 틀린 숫자를 말하면?** 숫자는 엔진만 만듭니다. AI 설명에 엔진에 없는 숫자가 있으면 자동으로 걸러 팀 힌트로 바꿉니다(`check_numbers`).
2. **엔진이 맞다는 걸 어떻게 아나요?** 단계마다 다른 방법으로 다시 계산해 비교하고, 기존 저장소 기준 정답 17문제 + 손 풀이 19문제(420개 항목)와 python-control로 대조했습니다. 무작위 1,000개에서 자체 검증 실패 0.
3. **중근은 어떻게 셉니까?** 유리수 범위 인수분해로 같은 인수가 몇 번 나오는지 셉니다. 수치 오차로 중근이 둘로 갈라지는 문제를 피합니다.
4. **이탈점 후보 중 버리는 기준은?** D′N − DN′ = 0 의 근에서 K = −D/N 이 양의 실수가 아니면 버립니다. 극대면 이탈점, 극소면 진입점(K″ 부호).
5. **Routh 표에서 첫 열이 0이면?** 첫 열만 0이면 ε, 행 전체가 0이면 보조방정식 미분. 이때 안정 범위는 폐루프 극점을 직접 계산해 정합니다.
6. **안정 범위 경계에 등호가 없는 이유?** 경계 K에서는 극점이 허수축 위(임계 안정)이므로 안정이 아닙니다.
7. **손글씨가 흐리면 오답 처리되나요?** 아니요. 확신도가 낮거나 읽을 수 없으면 '인식 확인 필요'로 따로 표시합니다.
8. **API 키는 어디 있나요?** 서버 환경변수에만. 브라우저 소스·네트워크 요청에는 없습니다.
9. **AI가 꺼지면?** 계산·채점·그래프·팀 힌트는 그대로 동작합니다. 시연 모드로 AI 흐름도 보여 줄 수 있습니다.
10. **왜 Python으로 바꿨나요?** 팀이 익숙한 언어이고, SymPy로 정확한 값(√, 분수)을 그대로 다룰 수 있어 설명과 검증이 쉽습니다.

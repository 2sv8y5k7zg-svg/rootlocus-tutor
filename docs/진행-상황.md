## 5. 2026-11-14에 드러난 문제와 제안한 판단 방법

**확인된 사실**
- RLocusGui(무료 웹판 RLDraw 있음, 영어): 근궤적, 규칙별 과정, K 변화에 따른 점 표시가 있다. 경민님이 직접 써 봄. 블록선도 입력 없음, 내 답을 넣어 확인하는 기능 없음, Routh 표 없음(K 범위는 표시).
- 그래서 "MATLAB 라이선스가 없어 확인할 수 없다"는 근거는 쓰지 않는다.

**확인되지 않은 가정**
- "일반 AI는 근궤적을 틀린다." 경민님 경험으로는 수치는 대부분 맞고 그림에서 틀린다. 실측은 아직 없다.
- 일반 AI가 코드를 실행해 그리면 그림도 맞을 수 있다.
- 일반 AI에 틀린 답을 주고 "어디서 틀렸나"를 물으면 맞히는지.

**예비 측정 결과(2026-11-14, Gemini 자동 모드, 8문제) — 자세한 내용은 검증/AI-오답률-결과-예비-2026-11-14.md**
- 수치: 문제 오답 1/8, 항목 오답 1/40. 틀린 것은 T12의 이탈점·진입점(원점 이중 극점을 한 개로 세어 실수축 구간을 잘못 잡음).
- 그림: 4/8 틀림. 코드·위젯으로 그린 3개는 정확했고(2개는 K 슬라이더 포함), 생성 이미지 1개와 글자 그림 3개가 틀렸다.
- 판단 기준(미리 정함): 8문제 중 2문제 이상에서 수치나 그림이 틀리면 방향 유지 / 그림만 틀리면 근거를 그림과 오답 진단으로 좁힘 / 수치·그림·진단이 모두 맞으면 주제 전환 검토.
- 현재 결론: 가운데 경우에 가깝다. "일반 AI는 수치를 틀린다"는 3장 근거로 쓰지 않는다. 그림은 "그리는 방식이 매번 달라 맞을 때와 틀릴 때가 섞이고, 틀렸다는 표시가 없다"로 쓴다.

- **결정 대기:** Claude의 의견은 "새 주제로 바꾸지 않고, 차별점을 'AI가 못 한다'에서 '숫자를 엔진으로 검증해 틀린 답이 나가지 않는다 + 정답 대신 힌트'로 바꾼다"였다. 경민님·주영님이 정한다. 정해지면 2·3·4장을 다시 쓴다.

**방향을 유지할 때의 논리**
- 정답을 보여 주는 도구는 이미 있다. 우리는 내 풀이가 어디서 틀렸는지 찾아 준다.
- 일반 AI는 틀릴 때 표시가 없고, 학생은 구분할 수 없다. 숫자를 엔진으로 묶은 구조가 그것을 막는다.

**2장(제시안)**: "근궤적 AI 튜터는 제어공학 수강생이 근궤적을 손으로 풀고도 어디서 틀렸는지 알 수 없는 문제를, 블록선도 사진 인식과 검증된 계산 엔진에 묶인 AI의 오답 진단·단계별 힌트로 해결합니다." 네 칸: 누구(제어공학을 수강하는 공학계열 학생) / 문제(정답을 보여 주는 도구는 있지만 내 풀이를 봐 주는 도구는 없다, 일반 AI는 숫자와 그림이 틀린다 + Gemini 캡처, 답지 사진) / AI(사진 → 전달함수, 틀리면 어떤 실수인지 되물음, 엔진 값만 쓰는 힌트) / 효과(처음부터 다시 풀기 약 10분 → 틀린 단계 하나만 다시).

**3장(제시안)**: 누가(제어공학을 수강하는 정보전기전자공학과 3학년) / 불편(과제가 블록선도로 나옴 → 손으로 9단계, 약 10분 → 답지·도구와 비교하면 다르다는 것만 앎 → 틀린 단계를 찾으려면 처음부터 다시 풀거나 물어야 함 → 일반 AI는 믿을 수 없음) / 근거(AI 오답률 + 설문) / 왜 우리(같은 수업을 듣는 두 명, 실수 목록을 만들 수 있음). "과제가 블록선도로 나온다"는 실제와 맞는지 확인이 필요하다.

**4장(제시안)**: 흐름 = 사진 또는 식 입력 → AI가 전달함수로(사용자 확인) → 엔진이 9단계 풀이를 계산하고 내 답과 대조 → 틀린 단계에서 AI가 되묻고 힌트. 비교표 = MATLAB rlocus, RLocusGui, 일반 AI, 우리(풀이 과정 표시, 블록선도 입력, 내 답 대조, 틀린 이유 안내, 숫자 신뢰). 한 줄 = "정답을 보여 주는 도구는 이미 있다. 우리는 내 풀이가 어디서 틀렸는지 찾아 준다. 숫자는 검증된 엔진이, 읽기와 되묻기는 AI가 맡는다."

**주의할 것**
